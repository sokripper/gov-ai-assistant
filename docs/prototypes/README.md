# AI 办公助手平台 · 交互原型交接说明

打开方式：浏览器直接打开 `index.html`（依赖同目录下的 `wechat-studio.css`、`wechat-layout-library.js`、`wechat-layout-adapter.js`、`wechat-studio.js`、`logo-梵行.svg` 与 `assets/` 本地素材，无需服务端；分享时请保留完整目录）。
目标视口：桌面 Web，基准 1440×900；适配目标为 1920×1080、1440×900、1366×768、1280×720、1024×768。

> 本原型用于需求验证与评审演示，不作为生产前端源码。生产前端建议按 React + TypeScript + Vite + Ant Design 重建。

## 一、本期能力

### 公众号编辑工作台（2026-09-17，本地未发布）

- 三栏保留：左侧内容与段落格式、中间整篇预览、右侧排版模板 / AI 定制 / 局部修改。
- 接入用户提供的本地「纯排版40套」完整 HTML：每批5套（共8批）、分类筛选、换一批；卡片和主预览使用当前文章与图片。配色跟随模板，收起独立配色页。旧18种演示风格保留代码兼容，但不再作为主入口。
- 正文适配使用实际标题、小标题和照片。模板目录使用实际小标题；问答、时间线、信息卡不凭空填入原文没有的问题、日期或署名。图片不足去空位，超出槽位续排；正文不截断，图片不重复。
- 2026-09-18新增统一头图设计入口：选择排版后确认短标题与参考图，同屏比较实拍设计版/AI创意版构图，选择后放回整篇；支持改字、换照片、3种本地构图示意、移除、撤销与会话版本恢复。换模板、改文章标题或删参考图会使旧头图失效，不自动沿用旧结果。
- 头图目前是明确标注的HTML构图草图，字体不是模型生成艺术字；生成要求只保存到会话内、状态awaiting_connection，没有API请求或扣用量。真实链路为Seedream静态成图→文字核对→人工确认，需要动态版本时再接Seedance。消息列表封面裁切另行验收。
- 模板已编译为同目录资源，不依赖模板库的8765服务；源目录未修改。来源清单、原始HTML和SHA256保存在 `wechat-layout-library.js`，更新方式见脚本说明。
- 已审正文保持只读；支持单段内选中字词后加粗、斜体、下划线、高亮、清除格式；引用、列表、标题样式、分隔线作用于整段，不支持跨段选区编辑。工具栏使用中文名称。文章标题、小标题、图注可单独修改，正文变更需返回素材重新确认。
- 局部修改页先列出具体对象，再进入相应的编辑项，避免依赖隐含的上一次选区。
- 图片增加、删除、撤销删除、排序、首图、裁切、比例与图注保留；单图或双图可以放在所选正文段后，编辑区与预览同步显示位置。新增图片不会清空原有排版。
- 支持撤销、重做、会话版本保存与恢复、成稿继续修改；刷新浏览器仍会清空，未接入持久化。
- 长图改字后返回草图待确认，原有成图不作为修改后结果；完整动效默认随同成稿展示。
- 普通图文导入去掉了模拟模型分析的延时过程，明确进入“手动试排”。真实模型按文章和照片推荐模板、配色、图文位置尚未接通，不用固定或随机匹配冒充智能推荐。AI 定制只演示部分规则调整并记录自由要求，未调用模型、未扣 Token、未实现新图片生成、完整格式复制、素材包导出或公众号发布。登录与单位用量不在本轮实现范围。
- 验证：新增40套模板集成测试69项通过（正文/图片完整性、并列结构、目录、修改与版本、0/1/2/8图、长文、长图流程）；原始模块45项及旧工作台回退路径25项也通过。参考库页面已查看；新版集成页面仍受本地URL预览策略限制，尚未完成五档尺寸视觉回归，也未验证微信粘贴兼容性。此前的视觉结论不能沿用。

## 六、分辨率策略

- `≥1280px`：完整侧边导航和桌面多栏布局。
- `1024–1279px`：侧边导航收为图标栏；公众号创作主区与预览区缩窄；数据工作台控制最小宽度；文档表格收起低优先级列。
- `<1024px`：不在本桌面原型验收范围内；如需移动端或平板端，应单独设计。公众号页面中的手机视图是“内容预览”，不是系统移动端适配。

## 七、原型边界

2026-09-18交付界面清理：用户流程不再展示模型名、实测标识、接口接入说明或开发备注。首屏仅保留图文/长图示例入口；开发能力边界保留在本说明与内部状态。界面使用“画面待更新”“设计要求已保存”等实际业务状态，不把未发生的生成、导出或发布描述为成功。新增10项产品文案检查及191项既有DOM/状态/CSS检查通过；不是浏览器像素级验收。

- 除“梵行科技调研”公开文章验证案例外，其余示例数据、单位名和文号均为虚构；该案例中的 AI 图片使用泛化虚构人物，不代表文中真实人员。
- 产业与政策研究默认不要求用户上传文件；当前“东西湖十五五”范文基于 5 个政府公开来源制作，正式版需实时检索、留存来源快照，并由编辑人员终审。
- 活动与宣传策划使用用户提供的历史方案提炼正式结构，但不把其中的人员名单、内部分工和未确认日期写入公开 Demo；模型只生成栏目、玩法、内容产品和传播节奏。
- 公众号页面会真实读取用户在浏览器中选择的本地图片并生成临时预览，但不会上传服务器；其他文件上传主要演示文件名和流程。
- 当前40套排版入口包含两路头图构图草图，不包含新生成的首图或其动效；故事模式保留 Seedance 实测完整动效，并作为同一长图式成稿中的动态段落呈现，不拆成另一份结果。
- 故事动漫长图先生成可编辑草图。用户确认标题和对白后，正式流程将确认文本连同构图约束提交 Seedream 做图字一体生成；最终预览直接使用文字已进入画面的栅格成图，不叠加网页文字层。成图后通过 OCR 与确认稿逐字比对；若用户再次改字，需要重新生成对应画面，而不是直接修改成图中的字符。
- 头图草图色调跟随当前模板，标题独立于文章长标题；二次修改须重新确认，不能将图字一体成图描述为直接改字。普通图文最终按钮保存的是方案，不是可发布的模型成图。
- 审定稿文件解析、导出 Word、导出素材包和真实图表下载均为产品入口示意。
- 本期不采集任意外部公众号，不承诺全网实时数据，也不把模型风险提示包装成审核通过结论。
- 知识库一期按单位空间统一管理；页面中的多知识库选择是检索范围，不是权限模型。
- Codex CLI 应作为可横向扩容的 Worker 池承接任务，不按用户部署独立 CLI。模型负责理解与生成；文件解析、存储、排版、图像处理、规则校验和任务状态由平台服务承接。
